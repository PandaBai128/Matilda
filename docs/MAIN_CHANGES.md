本文记录 `main` 从 GitHub 上一版 `origin/main`（`cc0d93b`）到当前版本（`1110cb0`）的改动。范围共 8 个提交，重点是将通用的 Clicky MiniMax 改造版进一步变成个人使用的“壮壮 / Matilda”。

## 1. 产品身份与个人缘起

- App 显示名改为“壮壮”，英文产品名和可执行文件名使用 `Matilda`；
- 菜单栏、控制面板、语音试听、ASR 关键词和错误提示统一使用壮壮身份；
- 原来的蓝色三角形替换为根据壮壮形象制作的透明头像；
- 应用图标和菜单栏图标同步更换，不再使用旧 Clicky 黑框图标；
- README 明确说明本项目源自 Clicky，但现在是围绕个人陪伴与日常屏幕问答形成的定制版本。

## 2. 跟随鼠标与状态动画

- 壮壮会在鼠标旁保持可配置距离，并提供快、中、慢三档跟随感；
- 鼠标移动时使用短生命周期的 60fps 平滑跟随，停止约 200 毫秒后立即停止更新；
- 空闲状态不再维持永久动画时钟，只在需要眨眼时短暂唤醒；
- 倾听、思考、回答和指向使用不同的按需动画频率；
- 支持自然眨眼、倾听波纹、思考倾斜和到达目标后的两次张嘴“汪，汪汪”；
- 默认鼠标静止 10 秒后自动隐藏，移动鼠标或开始语音交互时重新出现；
- 多显示器共用一个鼠标跟踪源，只在鼠标所在屏幕渲染头像。

## 3. 外观设置

新增独立的 Appearance 窗口，可以实时预览并调整：

- 头像大小；
- 与鼠标的距离；
- 跟随速度；
- 泛光颜色和强度；
- 自动隐藏时间；
- 指向圈大小与颜色；
- 是否显示目标中心点；
- “汪，汪汪”标签的背景颜色。

目标圈的中心始终保留模型返回的真实坐标，即使靠近屏幕边缘也不会为了避免裁切而移动中心。头像和文字标签可以进行边缘约束，但不修改目标点。

## 4. 连续对话和指向稳定性

- “点一下”“点击一下”现在会被识别为视觉指向请求；
- 明确说出一个新目标时，不再把上一轮目标描述和旧坐标带给模型；
- “怎么关掉它”“刚才那个在哪”这类依赖上下文的短追问仍保留上一轮对话；
- 普通知识、写作、抽象问题和地理问题继续保持不指向；
- 屏幕指向在代理层通过一次 MiniMax 函数调用返回目标边框，具体契约见下方第 10 节；不读取系统 Accessibility 控件树；
- 坐标是视觉模型根据截图作出的估计，目前适合作为辅助指引，不作为自动点击依据。

## 5. 连续语音与界面响应

- 流式 MP3 的解析、Audio Queue 生命周期和取消清理由专用串行队列处理；
- 用户开始下一轮说话时，可以取消上一轮 TTS，不等待缓慢的底层音频清理；
- 旧的音色试听和旧的流式响应不能在取消后重新播放；
- 网络或服务失败使用中性、准确的系统语音提示，不再误报“额度耗尽”；
- Release 版本不创建 `/tmp/clicky-debug.log`，也不记录转写、回答正文和屏幕衍生文本。

## 6. 构建、安装与权限

- 唯一建议安装位置为 `~/Applications/Matilda.app`；
- 每次通过 Xcode UI 测试后，需要再执行一次普通 Build，再替换安装版；
- 清理 DerivedData 和临时目录中的 `Clicky.app` / `Matilda.app` 副本，避免 Spotlight、Launch Services 和系统权限列表出现多个同名应用；
- 禁止通过终端运行 `xcodebuild`，避免签名和 TCC 权限实例变化。

## 7. 测试与当前边界

当前 Swift 单元测试覆盖：

- POINT 标签解析和坐标映射；
- 屏幕边角目标中心；
- 指向请求的正反例；
- 连续目标上下文；
- 鼠标跟随、自动隐藏和动画频率策略；
- TTS 预览取消、流式会话隔离和非阻塞清理；
- 权限路由和失败提示；
- 敏感正文不得写入日志。

Worker 测试覆盖 MiniMax TTS SSE 分块、上游取消和背压处理。

仍未实现：

- 自动点击、输入或执行脚本；
- 内置互联网搜索；
- 系统原生控件级的百分之百精准定位；
- 不依赖本地代理或 Cloudflare Worker 的直接 API 调用。

## 8. Codex 用量与下拉面板整理

- 壮壮菜单栏头像右侧可以显示 Codex 当前剩余用量，采用与 CPU / Memory 状态相近的上下两行轻量排版，不抢头像和语音陪伴功能的主视觉；
- 当前 Codex 只返回周限额，因此菜单栏和设置页只显示 `WEEK`。代码按窗口时长保留了 5 小时限额兼容，但在真实数据恢复前不会出现空列、灰色开关或占位提示；
- 用量默认使用自适应刷新：启动、唤醒后立即刷新；近期打开过壮壮或 Codex Usage 设置时每 2 分钟刷新，随后随空闲时间退到 5、15、30 分钟。低电量或系统温度压力较高时使用 30 分钟档；
- 设置页可以改用固定每 2、5、15、30 分钟刷新。选择会持久化，切换后重新安排下一次刷新，但不会额外制造一次即时请求；
- 刷新等待与正在进行的请求彼此独立：交互或切换档位只重排下一次等待，不会取消请求；同时发生的刷新会合并到同一个请求，避免唤醒刷新丢失或重复访问；
- 刷新失败保留上一次仍有效的成功快照，避免菜单栏因为短暂网络问题闪空；每个额度窗口到达恢复时间后会由一次性任务及时移除，不会在断网时继续展示过期百分比；
- 用量归零时可以选择显示紧凑的恢复倒计时，否则保持 `0%`；
- 新增独立的 Codex Usage 设置窗口，可以控制刷新频率、总开关、周限额显示和归零恢复时间。未来只有在接口真实返回 5 小时窗口后，才自动显示对应设置；
- 读取 Codex 本地已有的 OAuth 登录来查询用量，但不记录、不复制、不刷新，也不修改凭证。持久化内容仅包含最后一次成功的额度快照和界面偏好；
- 主下拉面板不加入 Codex 用量卡片。底部原来重复的 Voice Settings 入口改为 Codex Usage，语音设置仍保留在 Response 区域；
- 下拉面板统一为 Companion、Response、Recent 三个区块，使用一致的卡片边界、行高和分隔线；
- 原来占据整行的蓝色 Talk 测试按钮改为快捷键提示旁的小麦克风。录音时才变成紧凑的蓝色状态条，显示 Listening 和 Stop and send。
- Codex Usage 页头和下拉面板入口统一采用设计稿中的蓝色高低柱用量图标，不再使用通用仪表盘符号。

这组界面和数据边界是产品约束：后续审计或重构时，不要因为看到 5 小时解析代码就提前恢复占位 UI，也不要把 Codex 用量重新塞回主下拉面板。

## 9. 壮壮人格与菜单栏紧凑度

- 壮壮现在以安静、善于观察、聪明而温柔的成年伙伴为人格底色，对用户更亲近，偶尔自然流露一点无伤大雅的小狡黠；
- 人格只作为回答的轻微底色，不使用幼儿腔、狗叫、卡通小狗动作、固定口头禅或每句强行开玩笑；
- 延续陪伴不等于伪造记忆：壮壮可以温柔接住用户分享的往事，但不会声称自己记得未提供的过去，也不会通过依赖或内疚给用户压力；
- 人格提示词从中央状态管理器中提取为独立纯模块，回答长度、语言、屏幕理解、能力边界和指向规则仍保持原行为；
- 显示一个 Codex 额度时，菜单栏状态项宽度由 76 点收紧为 62 点；未来显示两个额度时由 126 点收紧为 104 点。内部内容的最小宽度为 59 点，因此保留约 1.5 点的单侧外缘；头像、百分比、标签字号和内部间距都不变。

## 10. M3.1 Flash 思考参数与屏幕定位工具（2026-10-20）

- 官方模型 ID 为 `MiniMax-M3.1-Flash`。M3.1 始终思考；Anthropic 请求发送 `thinking.type=adaptive` 和 `output_config.effort=low`。支持 low/medium/high/xhigh/max，代理默认 low；不再把思考深度误当成思考开关，也不再无意采用上游默认 max。
- M3.1 的思考占用 `max_tokens`，原 App 的 1024 token 预算可能只够思考而没有答案。代理默认至少 8192，可用 `MINIMAX_MAX_TOKENS` 调整；截断、无文本和未正常结束的流显式失败，触发 App 现有错误收尾，避免静默成功。
- 本地 Node 与 Cloudflare Worker 共用 `worker/minimax-chat.mjs`。定位请求提供只读 `point_to_screen` 函数，模型返回 `found/screen/bounds/label/spoken_text`；bounds 是该截图内 0–1000 的紧边框，代理校验后计算中心。
- 验证后的工具位置转换成现有 App 的 `[POINT_V2:x,y:label:screenN]` 标签。无效屏幕号、越界或反向边框、重复调用、缺少工具调用以及不存在的目标均返回 none，绝不回退到模型文本估计的坐标。
- 工具参数和思考内容不会进入朗读；自然语言答案仍流式输出。没有普通文本的有效工具调用用 `spoken_text` 补齐简短回答。
- 这次只具备截图理解与指示位置，不执行点击、键入、拖动或画图。Computer Use 评测分数不作为任意桌面定位准确率承诺；后续鼠标操作要在此校验结果和当前截图基础上接入。
- 用合成界面测量指示点是否落在已知目标框内，覆盖小关闭控件、相似按钮、多屏和目标不存在。测试工具及生成器保留在 `worker/test/`；不采集用户真实桌面或记录密钥。
- 本地配置保存后重启代理才生效；此次无需替换 Mac App。远端 Worker 源码与配置同步更新，未自动部署。
- 本次验证：29 项离线代理测试与 TypeScript 检查通过。经重启后的 `localhost:8787/chat` 和壮壮实际人格提示词，合成界面 7 项测试全部通过（6 个可见目标的中心落入已知目标框，1 个不存在目标返回 none），单项约 1.7–3.8 秒。它验证工具链与该样本，不等同于全桌面准确率。

## 11. API Computer 协议试用与定位试验台修复（2026-10-20）

- 新增 `MINIMAX_POINTING_MODE=computer/custom`；原自定义定位保留，模板和远端保持 custom，本机为用户试用切到 computer 并重启代理。无需 MiniMax Code、无需重建或替换 Mac App。
- 采用固定版本 OSWorld M3 公开参考提示词与 XML computer 动作格式，保留许可证；适配 macOS 环境，并强制只读单步定位。M3.1 Flash 可通过此 API 通道使用，无需回退 M3；不宣称完整复现官方 M3.1 评测。
- 默认只给当前主焦点截图，显式指定第 N 屏时选对应截图；新定位通道隔离旧对话和自定义工具提示，普通聊天不变。动作返回值只用于画指示圈，绝不执行鼠标点击、键入、滚动、拖动或代码。解析失败和不支持的动作不回退自定义工具，避免对比结果混淆。
- 32 项离线代理测试、TypeScript 和语法检查通过；直接真实 API 合成定位样本 7/7 通过（约 1.4–4.5 秒），不代表全桌面或全量 OSWorld 准确率。
- 网页浅色主题 `.light` 与 14px 红绿灯按钮共用类名，导致整个演示场景缩成 14×14px。样式限定为 `.traffic .light`，保留主题与按钮原本外观。测试页是手工复核工具，不自动访问 API，实验备注不改变代理配置。
- 重启后的本地代理 computer 通道再次 7/7 通过（约 1.1–2.7 秒）。页面 JS/CSS 静态回归通过，但 `file://` 可视自动化被工具安全策略阻止，刷新后的真实显示与手工计分未宣称验收通过，留给用户 Chrome 复核。
